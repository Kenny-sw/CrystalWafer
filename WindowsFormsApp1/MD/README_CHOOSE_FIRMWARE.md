# 📖 ИНСТРУКЦИЯ ПО ВЫБОРУ ПРОШИВКИ ARDUINO

## 🎯 Какую прошивку использовать?

В проекте есть **две версии прошивки** для управления шаговыми двигателями:

### 1️⃣ **StepperDriver_DirectWiring.ino** (Прямое подключение)

**Используй эту версию если:**
- Пины Arduino подключены **напрямую** к входам драйвера шаговых моторов
- У тебя стандартные драйверы типа TB6600, DM542, A4988, DRV8825
- В схеме **НЕТ** оптопар между Arduino и драйвером

**Логика сигналов:**
- `HIGH` на пине Arduino = активный сигнал для драйвера
- `LOW` на пине Arduino = неактивный сигнал
- STEP: импульс вверх (`LOW→HIGH→LOW`)
- ENA: `HIGH` = моторы включены, `LOW` = моторы выключены

---

### 2️⃣ **StepperDriver_OptocouplerWiring.ino** (Подключение через оптроны)

**Используй эту версию если:**
- Между Arduino и драйвером есть **плата с оптопарами** (оптронами)
- Входы драйвера подключены через светодиоды оптопар к питанию (+4В/+5В)
- Пины Arduino **стягивают** вход драйвера на землю через оптопару

**Логика сигналов (ИНВЕРСНАЯ):**
- `LOW` на пине Arduino = оптрон открыт = драйвер видит `HIGH`
- `HIGH` на пине Arduino = оптрон закрыт = драйвер видит `LOW`
- STEP: импульс вниз (`HIGH→LOW→HIGH`)
- ENA: `LOW` = моторы включены, `HIGH` = моторы выключены

---

## 🔧 Назначение пинов (одинаково в обеих версиях)

| Пин Arduino | Назначение | Описание |
|-------------|------------|----------|
| **2** | STEP_X | Импульсы шагов для оси X |
| **3** | STEP_Y | Импульсы шагов для оси Y |
| **4** | DIR_X | Направление движения оси X |
| **5** | DIR_Y | Направление движения оси Y |
| **6** | ENA | Включение/выключение драйверов (фиксация стола) |
| **7** | EDGE | Датчик края пластины (опционально) |

## ⚙️ Параметры профиля движения (настраиваются в коде или через ПК)

| Параметр | Значение по умолчанию | Диапазон | Описание |
|----------|----------------------|----------|----------|
| `minDelay` | 200 мкс | 100-5000 мкс | Минимальная задержка (максимальная скорость) |
| `maxDelay` | 800 мкс | 100-5000 мкс | Максимальная задержка (старт/стоп) |
| `accelPercent` | 30% | 10-50% | Процент шагов на разгон |
| `cruisePercent` | 40% | 0-80% | Процент шагов на постоянной скорости |
| `decelPercent` | 30% | 10-50% | Процент шагов на торможение |

**Важно:** Сумма `accelPercent + cruisePercent + decelPercent` должна быть ≈100%

## 🚀 Быстрый старт

### Шаг 1: Определи тип подключения

**Метод 1 - Визуальный осмотр:**
- Посмотри на плату между Arduino и драйверами
- Видишь **оптопары** (чёрные микросхемы 4-8 ног с маркировкой PC817, EL817, 6N137)? → Используй **OptocouplerWiring**
- Видишь только резисторы/прямые соединения? → Используй **DirectWiring**

**Метод 2 - Тестирование:**
1. Загрузи **DirectWiring**
2. Подключись через C# приложение
3. Попробуй зафиксировать стол и сделать шаг
4. **Не работает?** → Попробуй **OptocouplerWiring**

### Шаг 2: Загрузи прошивку

1. Открой нужный `.ino` файл в Arduino IDE
2. Выбери плату: `Tools → Board → Arduino Nano/Uno`
3. Выбери порт: `Tools → Port → COMxx`
4. Нажми `Upload` (стрелка вправо)
5. Дождись сообщения "Done uploading"

### Шаг 3: Проверь работу

1. Открой Serial Monitor (`Tools → Serial Monitor`)
2. Установи скорость **115200 baud**
3. После загрузки увидишь: `READY`
4. Если увидишь `EV S:0` или `EV S:1` - датчик работает ✅

## 🐛 Устранение проблем

### Проблема: Моторы не двигаются

**Проверь:**
1. ✅ Правильная прошивка загружена?
2. ✅ Стол зафиксирован? (в C# нажми "🔓 Фиксация")
3. ✅ Питание драйверов включено?
4. ✅ Правильные провода подключены к моторам?

**Попробуй:**
- Поменяй прошивку (Direct ↔ Optocoupler)
- Проверь логи в C# приложении

### Проблема: Моторы двигаются не в ту сторону

**Решение:**
В файле `.ino` найди функцию `doMoveCmd` и поменяй местами `true/false`:

```cpp
// Было:
case cmdStepXL:    X.moveProfile(steps, false); break;
case cmdStepXR:    X.moveProfile(steps, true);  break;

// Стало (если X двигается наоборот):
case cmdStepXL:    X.moveProfile(steps, true);  break;
case cmdStepXR:    X.moveProfile(steps, false); break;
```

### Проблема: Ошибка "ERR:UNLOCKED"

**Причина:** Стол не зафиксирован

**Решение:**
1. В C# приложении нажми кнопку "🔓 Фиксация"
2. Дождись изменения на "🔒 Сброс"
3. Теперь можно двигаться

### Проблема: Ошибка "ERR:CS"

**Причина:** Контрольная сумма пакета не совпадает (помехи в линии связи)

**Решение:**
1. Проверь качество USB кабеля
2. Убери источники помех от Arduino
3. Попробуй другой USB порт

## 📡 Протокол обмена с ПК

### Команды без данных:

| Команда | Код | Ответ | Описание |
|---------|-----|-------|----------|
| Lock | 0x05 | `EV L:1` + `OK` | Зафиксировать стол |
| Unlock | 0x06 | `EV L:0` + `OK` | Расфиксировать стол |
| SensorQ | 0x0B | `S:0` или `S:1` | Запросить состояние датчика |
| GetProfile | 0x08 | `PROFILE:200,800,30,40,30` | Получить текущий профиль |

### Команды с данными (6 байт):

| Команда | Код | Формат | Описание |
|---------|-----|--------|----------|
| MoveLeft | 0x01 | `[CMD][Steps:4байта][XOR]` | Двигать X влево |
| MoveRight | 0x02 | `[CMD][Steps:4байта][XOR]` | Двигать X вправо |
| MoveUp | 0x03 | `[CMD][Steps:4байта][XOR]` | Двигать Y вверх |
| MoveDown | 0x04 | `[CMD][Steps:4байта][XOR]` | Двигать Y вниз |
| SetProfile | 0x07 | `[CMD][minDelay:2б][maxDelay:2б][XOR]` | Установить профиль |

### События (асинхронные):

| Событие | Формат | Когда отправляется |
|---------|--------|-------------------|
| Датчик | `EV S:1` или `EV S:0` | При изменении состояния датчика края |
| Фиксация | `EV L:1` или `EV L:0` | При изменении состояния фиксации |

## 🔍 Отладка

### Включить подробные логи в Serial Monitor:

В начале `.ino` файла добавь:
```cpp
#define DEBUG_MODE
```

### Проверить работу датчика:

В Serial Monitor введи байт `0x0B` → получишь `S:0` или `S:1`

### Проверить состояние фиксации:

После команды Lock/Unlock должен прийти ответ `EV L:1` или `EV L:0`

## 📝 Изменения в коде

### Изменить назначение пинов:

Найди в начале файла:
```cpp
const uint8_t PIN_STEP_X = 2;  // Измени на нужный пин
const uint8_t PIN_STEP_Y = 3;
// ...
```

### Изменить скорость Serial:

Найди в `setup()`:
```cpp
Serial.begin(115200);  // Измени на 9600/57600/115200
```

**Важно:** Скорость должна совпадать с настройками в C# приложении!

### Настроить датчик:

```cpp
const bool EDGE_ACTIVE_HIGH = true;  // true = активный HIGH, false = активный LOW
pinMode(PIN_EDGE, INPUT_PULLUP);     // или INPUT, или INPUT_PULLDOWN
```

## 💡 Рекомендации

1. **Начни с DirectWiring** - работает в 80% случаев
2. **Проверь питание** - драйверы должны быть включены

## 🎓 Дополнительная информация

### Как работает трапецеидальный профиль?

```
Скорость
   ^
   │     ╱‾‾‾‾‾╲         ← Трапеция
   │    ╱       ╲
   │   ╱         ╲
   │  ╱           ╲
   └─┴─────────────┴──> Время
     Разгон Крейсер Торможение
     30%    40%    30%
```

**Преимущества:**
- Плавный старт без рывков
- Максимальная скорость на длинных дистанциях
- Плавная остановка без потери шагов

### Почему важна контрольная сумма?

USB-последовательная связь может искажать данные из-за помех. Контрольная сумма XOR позволяет обнаружить ошибки передачи и отклонить испорченный пакет.

### Почему нельзя вызывать Serial.print во время движения?

`Serial.print()` занимает 100-500 мкс - это нарушает точность timing'а шагов и может привести к потере шагов или рывкам мотора. События датчика отправляются **после** завершения движения или между командами.
